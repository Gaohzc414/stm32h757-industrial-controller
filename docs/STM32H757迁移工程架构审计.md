**双核职责划分（当前实际状态）**

| 核心 | Flash 基址 | 时钟 | 职责 |

## 2. Bootloader 分析

### 2.1 启动地址与 Flash 布局

| 分区 | 起始地址 | 大小 | Bank1 扇区 |
|------|---------|------|-----------|
| Bootloader (CM7) | `0x08000000` | 128KB | Sector 0 |
| APP Slot A（执行区） | `0x08020000` | 448KB | S1+S2+S3 + S4 前 64KB |
| APP Slot B（OTA 缓冲） | `0x08090000` | 448KB | S4 后 64KB + S5+S6+S7 |
| Bootloader/APP CM4 | `0x08100000` | ≤1MB | Bank2 |

- 链接脚本：`bootloader/Makefile/CM7/stm32h747xx_flash_CM7.ld`（`FLASH ORIGIN=0x08000000, LENGTH=128K`）
- **共享扇区 Sector 4**（`0x08080000`，128KB）被 Slot A 尾与 Slot B 头各占 64KB，
  是 A/B 槽交界处。擦除 Slot A 时必须先备份该 64KB 边界数据（见 `boot_slot_copy.c`）。
- 地址常量集中定义于 `bootloader/Common/Inc/boot_slot.h`。

### 2.2 APP 校验方式（`boot_slot_is_valid`）

| 槽 | 校验内容 | CRC |
|----|---------|-----|
| Slot A（执行） | ① SP 高字节 = `0x20`（RAM 地址）② Reset 向量落在 Slot A 段内且 thumb 位=1 | ❌ 不校验 |
| Slot B（OTA 缓冲） | footer 的 `magic=0x534F4F54`("SOOT") + `image_size` 合理 | ❌ 不校验 |

> ⚠️ **审计发现**：`boot_slot_footer_t` 内含 `image_crc32` 字段，但 `boot_slot_is_valid()`
> 与 `boot_meta` 的 `slot_crc[]` 均**未在启动校验路径中实际比对 CRC**。当前是"向量表轻量校验"，
> 而非"镜像完整性校验"——镜像内容损坏但向量表完好的情况无法被检测。若要求工业级可靠性，需补齐 CRC 校验。

### 2.3 跳转流程（`boot_jump.c` → `Boot_JumpToAppAt`）

1. `Boot_HoldCm4()`：清 `RCC->GCR` 的 `BOOT_C2` 位，将 CM4 保持在复位态
2. `__disable_irq()` 关全局中断
3. 停 SysTick（`CTRL/LOAD/VAL = 0`）
4. 清空 NVIC（`ICER[0..7]`/`ICPR[0..7]`）
5. 向 DTCM `0x2001FFF0` 写跳转魔数 `0xB00710AD`
6. `__set_MSP(app_stack)`、`__set_CONTROL(0)`、`DSB/ISB`
7. 内联汇编 `bx app_entry` 跳转至 `0x08020000`

**跳转魔数机制**：APP 的 `SystemInit`（`app/Common/Src/system_stm32h7xx_dualcore_boot_cm4_cm7.c`）
检测到 `BOOT_JUMP_MAGIC` 时先清标志，**仍执行完整的 RCC 复位**，避免 `SystemClock_Config()`
在 Bootloader 已配好的 480MHz 时钟上二次配置而卡死。这是双核 IAP 的关键安全设计。

### 2.4 boot_meta（`boot_meta.c`）

- 存储位置：**BKPSRAM** `0x38800000`（备份域 SRAM，掉电不丢）
- 结构：`magic/version/active_slot/pending_slot/boot_trial/flags/slot_crc[]/slot_size[]/crc32`
- 自校验：整体 CRC32（软件位翻转实现，非硬件 CRC 外设）
- 关键状态机：
  - `BOOT_META_FLAG_PENDING`（bit0）+ `boot_trial`（初始 3，即 3 次试启动）
  - OTA 完成后 `set_pending` → 重启 → bootloader 发现 pending 且 slot B 有效 → 拷贝 B→A →
    每次成功启动 `boot_trial--`，减到 0 才 clear pending；APP 正常运行后 `commit_pending`
  - 提供 A/B 回滚能力（虽然当前 `boot_meta_select_boot_slot` 固定返回 Slot A）

### 2.5 拷贝与 Flash 操作（`boot_slot_copy.c` + `bsp_flash_ram.c`）

- `boot_slot_copy_to_run_slot`：读 Slot B footer → 擦除 Slot A（保留共享扇区 64KB 边界）→ 256B 分片拷贝 → 重写 footer
- **Flash 擦写函数用 `__RAM_FUNC` 标记，链接到 `.RamFunc` 段，启动时从 Flash 拷贝到 RAM 执行**
  ——因为 CM7 从 Bank1 运行，擦写同 Bank 时若从 Flash 取指会冲突。这是正确且必要的设计。
- 擦除期间周期性 `IWDG1->KR` 喂狗，防复位。

### 2.6 CM4 处理方式

- Bootloader 阶段：CM7 等待 `RCC_FLAG_D2CKRDY` 标志确认 CM4 已进 STOP（带 `0xFFFF` 超时，未烧 CM4 固件也不会卡死），跳转前 `Boot_HoldCm4()` 拉住 CM4。
- Bootloader 的 CM4 镜像（`bootloader/CM4`）与 APP 的 CM4 镜像链接到**同一地址 `0x08100000`**，二者内容几乎相同（均为 CubeMX 的"进 STOP 等 CM7"模板），实为同一份占位固件。

## 3. APP CM7 分析

### 3.1 main 流程（`app/CM7/Core/Src/main.c`）

```
SystemInit（检测跳转魔数 → RCC 复位）
  → 等待 CM4 进 STOP（D2CKRDY，带超时）
  → HAL_Init + __enable_irq
  → SystemClock_Config（HSE 25MHz BYPASS，PLL→480MHz）
  → HAL_RCCEx_EnableBootCore(RCC_BOOT_C2) + HSEM_ID_0 唤醒 CM4
  → 外设初始化：
      GPIO → DMA → FMC → LTDC → DMA2D → ADC1 → SDMMC2 → FATFS
      → USART3 → USART1 → USART6 → SPI1
  → 应用初始化：
      BSP_Ota_Init / BSP_Ota_OnBoot
      BSP_Watchdog_LogResetCause
      mpu_memory_protection() + sdram_init()
      dht11_init() + lcd_init()
      MX_IWDG1_Init()（慢外设后启动，避免上电超时）
  → osKernelInitialize() → MX_FREERTOS_Init() → osKernelStart()
```

### 3.2 初始化顺序要点

- **时钟源差异**：Bootloader 用 HSI（64MHz 内振），APP 用 HSE（25MHz 外振 BYPASS）。
  二者独立配置，跳转后 APP 重新配置时钟是安全的。
- **MPU 先于 SDRAM**：`mpu_memory_protection()` 使 FMC/SDRAM 区域可缓存，再 `sdram_init()`。
- **IWDG 最后启动**：避免 LCD/DHT11 等慢速初始化期间喂狗不及导致复位。
- 时间基准：TIM6 周期中断 → `HAL_IncTick()`（`stm32h7xx_hal_timebase_tim.c`）。

### 3.3 FreeRTOS 任务列表

| 任务 | 优先级 | 栈 | 职责 |
|------|--------|-----|------|
| `defaultTask` | Normal | 2KB | 启动 USB/Modbus/DHT11/ADC/W5500/OTA，主循环喂狗 |
| `lvgl_task` | AboveNormal | 16KB | LVGL 主循环 `lv_timer_handler`（1ms 周期）+ 仪表盘刷新 |
| `watchdog` | — | — | 看门狗喂狗 |
| `dht11` | — | — | DHT11 温湿度采样 |
| `adc` | — | — | ADC 电压采样 |
| `ota` | — | 8KB | SOIP 协议处理 + Flash 擦写 |
| `w5500` | — | — | 以太网/DHCP/OTA TCP 链路维护 |
| `modbusSrv` | — | — | USB Modbus RTU 从站 |
| `mbCoilStore` / `mbCoilRestore` | — | — | 线圈持久化（Flash NV）/ 上电恢复 |

- 任务创建位置：`freertos.c`（defaultTask）、`lvgl_demo.c`（lvgl_task）、各 BSP 模块内部（其余）。
- **OTA 协作挂起**：`bsp_ota_coop_register(task)` 将 defaultTask/lvgl_task 注册为协作 peer，
  OTA 擦写 Flash 时挂起它们，避免并发访问 Flash。

### 3.4 外设初始化映射（CM7）

| 外设 | 用途 |
|------|------|
| FMC + SDRAM | 外部 8MB SDRAM（LVGL 帧缓冲 + OTA 备份区） |
| LTDC + DMA2D | LCD 显示控制器 + 2D 加速 |
| ADC1 | 电压采样（mV） |
| SDMMC2 + FatFs | SD 卡文件系统 |
| USART1/3/6 | USART1 调试 printf + Modbus/调试 |
| SPI1 | W5500 以太网芯片 |
| USB (CDC) | USB Modbus 通道 |

## 4. APP CM4 分析

### 4.1 CM4 入口（`app/CM4/Core/Src/main.c`）

```
Reset → SystemInit（CORE_CM4：设置 VTOR=0x08100000）
  → 使能 HSEM 时钟
  → HAL_HSEM_ActivateNotification(HSEM_ID_0)
  → HAL_PWREx_EnterSTOPMode(..., PWR_D2_DOMAIN)   // D2 域进 STOP，等 CM7 唤醒
  → HSEM 唤醒后清标志
  → HAL_Init + MX_DMA_Init
  → while(1) 空转
```

### 4.2 负责功能

**当前无实际功能**。CM4 是 CubeMX 双核模板的最小 stub：
- 仅初始化 DMA（`MX_DMA_Init`），无任何外设或任务
- 主循环空转，不参与任何业务

### 4.3 与 CM7 通信方式

- **唯一交互**：`HSEM_ID_0` 硬件信号量 + D2 域 STOP/WFE 启动握手
  （CM4 上电即进 STOP，CM7 通过 `HAL_RCCEx_EnableBootCore(RCC_BOOT_C2)` 唤醒）。
- **无 IPC 框架**：代码中未发现 OpenAMP / RPMsg / VIRT_UART / 共享内存消息队列等双核通信机制
  （已全仓 grep 确认）。双核共享物理内存空间（AXI SRAM / D2 SRAM），但未定义任何跨核共享数据结构。

> 结论：**CM4 目前是"被唤醒的空核"**，双核 IPC 是迁移后待实现的主要工作项之一。

### 5.1 各模块要点

- **OTA**（最完整模块）：`bsp_ota_manager/protocol/transport/flash/crc/coop/uart/app`
  组成完整 SOIP v2.0 协议栈，A/B 槽 + 试启动 + pending commit。
  传输通道：**W5500 TCP**（主），`bsp_ota_uart.c` 为辅助调试接口。
- **Modbus**：libmodbus 协议栈（`Middlewares/Third_Party/libmodbus`）+ USB CDC 传输，
  线圈映射含 PA3 LED 控制，支持线圈 Flash 持久化（NV）。
- **W5500**：Wiznet 官方驱动移植 + FreeRTOS 任务，负责 DHCP/TCP 链路维护与 OTA 连接。
- **ESP8266**：**遗留模块**——`bsp_esp8266.mk` 存在但**未在 `app/Makefile/CM7/Makefile` include**，
  `StartDefaultTask` 也未调用其启动函数，因此**未编译进固件**。W5500 是以太网主通道，ESP8266 为备用 WiFi 方案。
- **触摸**：同时支持 GT1151（GT9xxx）与 FT5206 两套控制器，`lv_port_indev.c` 做抽象。
